# Canon v2.8 — amendment proposal (draft, for ratification)

**Status:** RATIFIED — folded into canon 2.8.0 (with the `merge_target`
tunable added at ratification). Kept as the decision record; the canon
(`specline-2.8.md`) is the law.

**Posture.** One change at the *provable* altitude, additive and
non-breaking — a v2.7 spec stays valid. Shaped against the first external
runner (git-treeline/orchestrator, a conforming 2.7 runner) hitting the
same wall from three independent directions — not a theoretical gap.
Per the research posture (`docs/research/findings.md`: *"decide from runs,
not theory"*) — this proposal is from a run.

---

## The runnable-command entry shape

**Change.** An `agent-loopable` acceptance item MAY carry its command in a
fixed entry shape — the same move v2.3 made for `status.md` entries
(`### status.md schema`, *Machine-parseable entries*: `Last green
checkpoint`, `Dead ends`, `Corrections` each carry a fixed convention a
runner parses without interpreting prose):

```markdown
### agent-loopable
- Limit tests pass — run: `swift test --filter ProviderLimitTests`
- Composer renders the disabled state under a simulated 429
```

Grammar: `<claim> — run: `​`<command>`​``. The command is a single shell
invocation; exit 0 settles the claim true. An item without the suffix is
unchanged — the implementer's grounded assessment, exactly as B5 already
allows (*"a runnable command is the strongest form, not the required
form"* — canon, provable altitude). **The suffix is never required**;
Specline checks only the *shape* of items that opt in (a malformed
`— run:` warns — `CHECK-RUN-MALFORMED`, advisory), and never demands one
exist.

**Why (three consumers, one wall).** All three are the same external
runner (git-treeline/orchestrator) hitting the same missing surface from
different angles:

1. **The loop's progress trigger is unmeasurable without it.** The canon
   defines a `loop_budget` cycle as an iteration with no green-checkpoint
   advance (*Escalation — `loop_budget` and `stale_after` coexist*) — but
   with prose-only checks, no runner can tell red from green except by
   trusting the implementer's own report. A runnable subset gives the
   runner an independent advance signal.
2. **The verifier can hold the ruler.** A fresh-context reviewer that can
   *execute* the frozen checks (rather than read a diff) grades against
   ratified evidence, not interpretation. This is B5's frozen-checks rule
   (provable checks are "authored before the build and frozen relative to
   the implementer") made mechanical where mechanization fits.
3. **Surfaces can show check state honestly.** A cockpit rendering the
   acceptance partition can only show live pass/fail for items a machine
   can settle; today it would have to fake it or omit it.

**What this deliberately is not:** not rspec-style spec definitions, not
a new file, not a second format, not a requirement that behavior be
testable by command. The v2.6 posture — a runnable command is the
strongest form of evidence, not the required form (B5; also restated at
canon ~L682, *"strongest form of that evidence, not the only one"*) — is
unchanged; this amendment only makes the strongest form machine-findable
when the author already has it.

**Failure mode (named, per canon discipline — a claim without a failure
mode is marketing):** commands rot as code moves. Mitigation is already
in the canon: checks are frozen at ratification, so a rotted command
fails loudly in the loop and escalates through the existing amendment
mechanics (re-ratification bumps the contract) — it cannot be quietly
rewritten by the implementer it measures. Expected band: same as the
mid-build revision rate.

**Enforcement (Specline):** advisory only. New rule `CHECK-RUN-MALFORMED`
(warn): an `agent-loopable` item containing `— run:` whose remainder is
not a single backtick-fenced command. No rule fires on absence.

**Runner note (non-normative):** a Specline-compliant runner executing
the runnable subset SHOULD record results against the item text in its
own state and reflect advances in `status.md`'s Last green checkpoint;
the folder remains the interop surface, per the 2.7.1 runner contract
(*"The runner contract is file-observable state, not a wire format"*).
This is guidance layered on that contract's existing three MUST-items
(handoff state, bounce verdict, escalation reason) — it does not add a
fourth.

## New doctor rules

| rule_id | fires when |
|---|---|

## Migration — non-breaking

- The `— run:` suffix is optional; every existing `agent-loopable` item
  without it stays exactly as valid as it is today.
- `CHECK-RUN-MALFORMED` only inspects items that already contain the
  literal `— run:` marker — it has nothing to say about the rest of a
  spec.
- No frontmatter field, no new file, no new required section. The one
  new surface is a fixed sub-grammar inside an existing, optional list
  item.

## Open decisions (for ratification)

1. **Rule id name.** `CHECK-RUN-MALFORMED` (recommended — mirrors
   `JUDGEABLE-NO-SECTION`'s naming: partition + failure shape).
2. **Enforcement severity.** Advisory (warn), never blocking (recommended
   — matches the preserved v2.6 posture: the suffix is opt-in, so its
   malformation can only ever be advice, not a gate).
3. **Version.** `2.8.0` (recommended — an additive optional entry shape
   plus one new advisory doctor rule is the same class of change as
   v2.4's `judgeable` partition or v2.5's `## Corrections` section, both
   MINOR bumps; nothing here breaks a v2.7 spec).
4. **Runner-note normativity.** Stays a non-normative SHOULD appended to
   the existing 2.7.1 runner contract, not a fourth MUST-externalize item
   (recommended — the contract's three MUST-items are about handoff
   survivability; this is about a runner *using* the new signal well,
   not about interop).

## Cost, honestly

One optional entry-shape grammar inside an existing acceptance-item list,
one new advisory doctor rule, one non-normative sentence appended to the
2.7.1 runner contract. No new file, no new frontmatter field, no new
required section. All additive, all non-breaking. The genuinely new
surface is the sub-grammar itself — everything else (the frozen-checks
rule, the "strongest form, not required form" posture, the folder-as-
interop-surface runner contract) is cited, not changed.
